# Lenta: end-to-end uplift-моделирование

[Графики и результаты полного запуска](results/README.md) · [Бизнес-отчёт](results/report.md) · [Метрики](results/metrics.csv)

В публичном репозитории сохранены код и агрегированные результаты. Индивидуальные
прогнозы, списки строк train/test и сериализованные модели/препроцессор создаются
локально при запуске и исключены из публикации через `.gitignore`.

Проект оценивает изменение вероятности визита после SMS и сравнивает рассылку
всем клиентам с рассылкой верхним 30% по прогнозу uplift. Используется открытый
Lenta Uplift Modeling Dataset, загруженный через `sklift.datasets.fetch_lenta()`.
Истинный CATE отсутствует и нигде не используется.

## Установка и запуск

Код рассчитан на Python 3.10+. Полный запуск проверяется на Windows, Python 3.12.
Для Python 3.10 выбран causalml 0.15.5; для Python 3.11+ — 0.16.0.
Ветка Python 3.10 отдельно не запускалась. Python 3.12 рекомендуется для
воспроизведения приложенных результатов. На полном датасете нужен запас RAM
для плотных матриц и OLS; сначала можно проверить установку на подвыборке.

Из каталога `project`:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py --cache work/data --output results
```

Воспроизведение проверенного окружения Python 3.12:

```bash
python -m pip install -r requirements-lock-py312.txt
python main.py --cache work/data --output results
```

Быстрый пример на 12 000 строк реального датасета; это не итоговая оценка:

```bash
python main.py --sample-size 12000 --trees 5 --importance-rows 1000 --permutation-repeats 1 --output demo_results
```

Денежный сценарий с **условными**, заменяемыми параметрами: 2 денежных единицы
за SMS и 500 денежных единиц маржинального дохода за дополнительный визит:

```bash
python main.py --sms-cost 2 --visit-margin 500 --output scenario_results
```

Стоимость и маржа должны быть в одной валюте. Используется маржа, не выручка.
Без этих параметров программа не выдумывает денежную прибыль. `--save-models`
сохраняет обученные модели; OLS может давать большой файл. Загружайте joblib
только из доверенного источника.

## Данные и защита от утечки

В загруженном датасете 687 029 строк и 193 признака: 191 `float64`, один
`object`, один `int64`. Treatment: 515 892 (75,09%), control: 171 137 (24,91%).
Визит совершили 74 368 клиентов (10,82%). Описательная частота визита:
treatment 11,013%, control 10,258%; это EDA, не метрика обученной модели.
Пропуски есть в 153 признаках; полностью пустых колонок нет. Наибольшая доля
пропусков — 72,23% у `k_var_sku_price_15d_g49`. Полный аудит — `results/eda_columns.csv`.

1. `group=test/treatment` преобразуется в 1, `control` — в 0; неизвестные
   значения вызывают ошибку. Название `group=test` означает воздействие, а не holdout.
2. Разбиение 80/20 стратифицировано по `2*treatment + target` при seed=42:
   549 623 обучающих и 137 406 тестовых клиентов.
3. Идентификаторы, treatment и исход не поступают в признаки. `gender` и
   `main_format` трактуются как категориальные, даже если формат числовой.
4. `FeatureEngineer.fit` видит только train. Исходные числа заполняются
   train-медианами, после чего применяются заранее заданные формулы.
   Если train-колонка полностью пустая, вместо неопределённой медианы используется 0.
5. Категориальные пропуски заменяются на `unknown`. OneHotEncoder с
   `handle_unknown='ignore'` обучается только на train; неизвестная test-категория
   получает нулевой код. `drop='first'` уменьшает линейную избыточность для OLS.
6. Медианы новых неопределённых значений, StandardScaler и словарь OHE также
   обучаются только на train. После OHE в проверенном запуске 198 столбцов.
7. Test используется только для преобразования фиксированными правилами,
   сравнения, интерпретации и графиков. На test нет fit, подбора параметров,
   ранней остановки или отбора признаков. Общий EDA не меняет правила пайплайна.

`response_sms` и `response_viber` в описании источника — отклики на **предыдущие**
коммуникации. При переносе на другие данные обязательно проверяется их доступность
до текущей SMS. Причинная трактовка предполагает рандомизированное назначение,
отсутствие влияния между клиентами и общий механизм наблюдения исхода. Этот код
не исправляет скрытое смешение в наблюдательных данных.

## Новые признаки

| Признак | Формула | Интерпретация |
|---|---|---|
| `purchase_variability` | Среднее всех числовых `k_var_*` | Общая нестабильность покупок; смешивает разные окна и категории |
| `promo_dependency` | `promo_share_15d / (promo_share_15d + 1)` | Сжатая промо-зависимость; при доле 0–1 лежит в 0–0,5 |
| `communication_response` | `response_sms + response_viber` | Историческая восприимчивость к коммуникациям; сумма не является вероятностью |
| `avg_check` | `total_spend / num_transactions` при счётчике > 0 | Средний чек при совпадающих периодах исходных полей |

В настоящей Lenta нет `total_spend` и `num_transactions`, поэтому `avg_check`
**не создаётся**. Суммы по частичным товарным группам не подменяют общий чек.
Нулевые знаменатели дают NaN с последующей train-импутацией. Промо-преобразование
монотонно и не добавляет новой информации само по себе; композиты коррелируют
с исходными фичами. Список реально созданных признаков, источники и обоснования
сохраняются в `results/new_features.json`.

## Модели

- **S-Learner:** ровно `causalml.inference.meta.LRSRegressor`. Это OLS с
  treatment как дополнительным столбцом. Без взаимодействий uplift константный:
  `f(X,1)-f(X,0)=beta_t`. Он оценивает средний эффект, но не ранжирует клиентов.
  Численная погрешность вычитания убрана; ожидаемый Qini AUC равен 0.
- **T-Learner:** `BaseTRegressor` с XGBoost для каждого плеча. Цель
  `reg:logistic` даёт вероятностные прогнозы бинарного исхода.
- **X-Learner:** `BaseXRegressor`, два XGBoost исхода с `reg:logistic` и два
  XGBoost псевдоэффекта с `reg:squarederror`. Propensity фиксирована как доля
  treatment в train и передаётся явно также при предсказании; test treatment
  для предсказания не используется. Это предполагает постоянную вероятность назначения.
- **Uplift Random Forest:** `UpliftRandomForestClassifier`, 50 деревьев,
  глубина 5, `min_samples_leaf=500`, `min_samples_treatment=100`, KL-критерий.

У XGBoost 120 деревьев глубины 4, learning rate 0,05, subsample/colsample 0,8,
L2=5. Никакого поиска гиперпараметров. Во всех случайных процедурах seed=42;
у детерминированного OLS аргумента random_state нет. Между версиями библиотек
и платформами возможны небольшие численные различия.

## Метрики и экономическая трактовка

**Qini AUC** — `sklift.metrics.qini_auc_score(..., negative_effect=True)` с
нормировкой библиотеки. Это площадь сверх случайной политики, нормированная
эмпирической идеальной кривой. Её построение не требует ground truth CATE.
Результат не следует смешивать с ненормированными баллами других реализаций Qini.

**Uplift@30%** — разница `mean(y|t=1, top) - mean(y|t=0, top)` внутри единого
топа размером `ceil(0.3*N_test)`. Это не средний прогноз uplift. Общий топ
соответствует стратегии `overall`; разбиение на равных прогнозах случайное,
воспроизводимое и не зависит от target/treatment. Децили несуммарные: первый —
верхние 10%, второй — следующие 10%. Интервалы — нормальная аппроксимация
разницы двух долей, без поправки на множественные сравнения и выбор победителя.

Прогнозные инкрементальные визиты:

```text
visits_top = mean(pred[top]) * len(top)
visits_all = mean(pred) * len(test)
visits_lost = visits_all - visits_top
sms_saved = len(test) - len(top)
profit_top = visits_top * visit_margin - len(top) * sms_cost
profit_all = visits_all * visit_margin - len(test) * sms_cost
profit_top - profit_all = sms_saved * sms_cost - visits_lost * visit_margin
```

Отрицательные «потерянные» визиты означают прогнозный выигрыш от отказа от SMS
части клиентов. Прогнозные суммы зависят от калибровки моделей, которую высокий
Qini сам по себе не гарантирует. Дополнительно сохраняется оценка `разница долей × N`
по наблюдаемым treatment/control. Поскольку исход бинарный, «инкрементальные
визиты» здесь означают дополнительных клиентов хотя бы с одним визитом за
период; число всех транзакций так оценить нельзя.

Победитель выбирается по test-Qini **для сравнительного анализа**, как задано
в задаче. Его окончательная оценка после такого выбора оптимистична. Для
решения о внедрении требуется новый holdout или рандомизированный пилот.
Тестовая feature importance не используется для переобучения/отбора признаков.

- `qini.png`: четыре Qini-кривые и случайная политика.
- `uplift_deciles.png`: разница долей и приблизительные 95%-интервалы по децилям.
- `uplift_matrix.png`: **условная иллюстрация**, а не выявленные причинные типы.
  Вероятности `p0/p1` берутся у T-Learner, порог заранее установлен в 0,10
  и меняется через `--segment-threshold`. Комбинации «низкая/высокая» подписаны
  привычными названиями persuadables, sure things, lost causes, sleeping dogs.
  Обе потенциальные реакции одного человека ненаблюдаемы; их совместное
  распределение не идентифицируется даже при известных p0/p1. Пороговые группы
  не являются оценкой истинной численности четырёх причинных типов.
- `feature_importance.png`: 15 наибольших падений Qini при перестановке
  признаков до OHE на стратифицированной подвыборке **test** из 5 000 клиентов,
  три перестановки каждого признака. Стандартное отклонение отражает только
  эти повторы, не общую неопределённость. Отрицательные важности не обнуляются.
  Перестановка композита отдельно от его источников меняет их согласованность;
  корреляция ограничивает трактовку отдельных значений. Знак причинного влияния
  такая важность не показывает. Бизнес-смысл каждого из топ-15 — в `results/report.md`.

## Если causalml не устанавливается

Создайте чистое окружение и выполните:

```bash
python -m pip install -r requirements-core.txt
python main.py --backend sklift --output fallback_results
```

В этой ветке S = `sklift.SoloModel(LogisticRegression)`, T =
`sklift.TwoModels(XGBClassifier, XGBClassifier)`, X = собственная явная
реализация X-Learner на XGBoost, четвёртая модель = регрессия случайного леса
на transformed outcome `y*(t/p-(1-t)/(1-p))`. Последняя формула учитывает долю
воздействия около 75%, а не предполагает 50/50.

В scikit-uplift нет прямой замены `UpliftRandomForestClassifier`; поэтому
четвёртая модель явно названа `Transformed-outcome RF (fallback)`. Этот режим
не выдаёт другую модель за запрошенный uplift forest. Он полностью проверен
на 12 000 строк Lenta, но его результаты нельзя смешивать с основным прогоном.

Если загрузка не удалась, проверьте доступность источника и место на диске;
при повреждённом кеше задайте новый `--cache`. Исключение логируется и
передаётся вызывающему коду; синтетические данные вместо Lenta не подставляются.
Сообщение causalml об отсутствии необязательного `duecredit` не препятствует
обучению и не относится к вычислительным результатам.
